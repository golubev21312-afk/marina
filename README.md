# Крафт — сайт мастерской

Сайт-витрина мастерской «Крафт» (Нижний Тагил): изделия из дерева с ручной
росписью. Продаж через сайт нет — кнопки «Заказать» ведут в диалог ВК
(`vk.me/craftthandmade`).

- **Сайт** — Vite + React 19 (JavaScript), 3D-матрёшка на three.js, анимации GSAP.
- **База** — [PocketBase](https://pocketbase.io) 0.40.5: изделия, разделы,
  карусель главной, статистика, журнал ошибок. Фото изделий хранятся там же.
- **Админка** — `/admin` на самом сайте: в ней мастер ведёт изделия, разделы и
  карусель. Сайт обновляется сразу, без пересборки.

## Что нужно

- Node.js 22+
- `backend/pocketbase.exe` — программа базы, в git её нет. Скачать
  `pocketbase_0.40.5_windows_amd64.zip` со страницы
  [релизов](https://github.com/pocketbase/pocketbase/releases/tag/v0.40.5)
  и положить exe в `backend/`. Для Linux — `pocketbase_0.40.5_linux_amd64.zip`,
  файл `backend/pocketbase`. Для macOS — `pocketbase_0.40.5_darwin_amd64.zip`
  (на Apple M — `darwin_arm64`), тоже `backend/pocketbase`. `npm run db`
  сам выберет нужный файл.
- Google Chrome — только для автотестов.

```sh
npm install
```

## Запуск

Два окна терминала:

```sh
npm run db                      # база: http://127.0.0.1:8090
npm run dev -- --host 127.0.0.1 # сайт: http://127.0.0.1:5173
```

Открывать **по IP `127.0.0.1`, не `localhost`**: без `--host` Vite слушает
только IPv6, и страница по `localhost` может не открыться.

Сайт ходит в базу через прокси Vite (`/api`, `/_/` → 8090), поэтому база
должна быть запущена — иначе каталог пустой.

| Адрес | Что там |
| --- | --- |
| `http://127.0.0.1:5173/` | сайт |
| `http://127.0.0.1:5173/admin` | админка мастера (учётка из коллекции `editors`) |
| `http://127.0.0.1:8090/_/` | панель PocketBase (суперпользователь): схема, записи, бэкапы, журнал ошибок `client_errors` |

Пароли в репозитории не хранятся.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run db` | база с миграциями и хуками |
| `npm run dev -- --host 127.0.0.1` | сайт для разработки |
| `npm run build` | сборка в `dist/` |
| `npm run lint` | линтер (oxlint) |
| `npm run test:e2e` | автотесты — гонять перед каждым коммитом |
| `npm run stories` | пересобрать запасные истории из `content/stories-source.txt` |

## Автотесты

`npm run test:e2e` — Playwright в установленном Chrome, около минуты.
`tests/e2e/server.mjs` собирает сайт и поднимает PocketBase на **чистой
временной базе** (порт 8095, как на хостинге — с хуками), настоящую
`backend/pb_data` не трогает. Тесты: вход, разделы, изделия, карусель,
пароль, статистика, страницы сайта, 3D-сборка, превью для ВК, переход в ВК,
шрифты, режим без 3D, «Уменьшить движение».

То же самое GitHub делает сам на каждый коммит (`.github/workflows/check.yml`):
линтер, сборка, автотесты на Linux. Результат — вкладка **Actions** в
репозитории и значок ✓/✗ у коммита; у упавших тестов там же снимки экрана.

```

  pages/       изделие, заказ, о мастерской, политика, 404
  components/  каталог, карточки, меню, ящерки, предупреждение перед ВК
  admin/       админка
  lib/         клиент базы, товары, разделы, статистика, ошибки
  data/        факты, запасные истории, реквизиты (operator.js)
  styles/      темы (tokens.css), «Малахит», украшения, шрифты
  theme/       переключение тем «Белая» / «Малахит»
public/        модели .glb, картинки, текстуры, шрифты (свои, не с Google)
content/       тексты заказчика — дословно, не переписывать
backend/
  pb_migrations/  схема базы — каждое изменение отдельной миграцией
  pb_hooks/       превью ссылок для ВК, чистка статистики и журнала ошибок
  pb_data/        живая база и фото — в git нет, беречь
tests/e2e/     автотесты
```

### База

Схема меняется **только миграциями** в `backend/pb_migrations` (файл
`<число>_<что>.js`, у каждой есть откат). PocketBase применяет новые
миграции сам при запуске `npm run db` — после добавления миграции базу
надо перезапустить. Перед изменениями на живой базе — копия `pb_data`.

Коллекции: `products` (изделия; наличие — `stock`: в наличии / под заказ /
нет в наличии), `categories` (разделы), `showcase` (карусель главной),
`editors` (учётка мастера), `visits` (свой счётчик посещений),
`client_errors` (ошибки у посетителей, хранятся 30 дней).

Автобэкапы — каждые 3 часа, хранятся последние 16, в
`backend/pb_data/backups` (настройка в миграции `1727651600_backups.js`).

## Настройки перед выкладкой

- **Яндекс.Метрика** — скопировать `.env.example` в `.env`, вписать номер
  счётчика в `VITE_YM_ID` и пересобрать. Пусто — Метрики и плашки о cookie
  нет, работает только свой счётчик (вкладка «Статистика» в админке).
- **Реквизиты** для политики персональных данных — `src/data/operator.js`
  (ФИО, ИНН, почта, адрес сайта, хостинг). Пропуски — значения
  в `[квадратных скобках]`, на странице `/privacy` они подсвечены.

## Выкладка на хостинг

На хостинге PocketBase сам раздаёт собранный сайт — Vite там не нужен.

1. VPS в России (Ubuntu), домен → A-запись на IP сервера.
2. На сервер: `pocketbase` для Linux (0.40.5), `backend/pb_migrations`,
   `backend/pb_hooks`, сборку `npm run build` (папка `dist` → `pb_public`)
   и `pb_data` (перенести текущую базу).
3. Запуск (лучше службой systemd):
   ```sh
   ./pocketbase serve ДОМЕН --dir pb_data --publicDir pb_public \
     --migrationsDir pb_migrations --hooksDir pb_hooks
   ```
   С доменом PocketBase сам получит HTTPS-сертификат (нужны порты 80 и 443).
4. В `/_/` → Settings: Application URL = `https://ДОМЕН`; почта (SMTP) —
   без неё не работает «Забыли пароль?» в админке.
5. Превью ссылок в ВК (`pb_hooks/og_*`) работает только так — когда сайт
   раздаёт PocketBase; при `npm run dev` хуки не участвуют.
